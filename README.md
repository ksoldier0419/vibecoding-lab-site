# Teaching Site

이 폴더는 `teaching/materials`와 `teaching/courses`를 바탕으로 만든 정적 사이트 결과물입니다.

공개용 저장소 `vibecoding-lab-site`로 복사한 뒤 GitHub Pages 또는 Vercel로 배포할 수 있습니다.

로컬에서 확인할 때는 프로젝트 루트에서 다음 명령을 실행합니다.

```powershell
python -m http.server 8000 -d teaching/site
```

브라우저에서 다음 주소를 엽니다.

```text
http://localhost:8000/
```

자료실은 다음 주소에서 확인합니다.

```text
http://localhost:8000/materials/
```


## Google 로그인 로컬 실습

`feature/google-login` 브랜치의 개발용 기능이다. 운영 `main`에 병합하거나 Vercel에 배포하기 전 단계다.

1. Node.js 22 이상에서 `npm ci`를 실행한다.
2. `.env.example`을 `.env.local`로 복사한다.
3. `GOOGLE_CLIENT_ID`에 개발용 클라이언트 ID를 입력한다.
4. `SESSION_SECRET`에는 충분히 긴 임의 값을, `LOGIN_ALLOWED_EMAILS`에는 테스트 계정 이메일을 입력한다. 여러 계정은 쉼표로 구분한다.
5. `.env.local`에 테스트 DB의 `DATABASE_URL`을 추가하고 `npm run db:setup`을 실행한다.
6. `npm run dev`를 실행하고 `http://localhost:3000/login.html`을 연다.

Google Console의 승인된 JavaScript 원본에는 `http://localhost`, `http://localhost:3000`을 등록한다. 리디렉션 URI와 Google 클라이언트 보안 비밀번호는 이 팝업 방식에서 사용하지 않는다.

Google 공식 라이브러리가 ID 토큰의 서명·대상·발급자·만료를 검증한다. 서버는 로그인 요청의 출처, 임시 확인값(nonce), 허용된 테스트 계정도 검사한다. 인증된 Google 고유 ID로 사용자를 식별하며 교수 권한이나 수강생 자격을 부여하지 않는다.

세션은 Neon DB에 최대 한 시간 보관한다. 쿠키는 HttpOnly·SameSite=Lax이며 HTTPS 배포에서는 Secure를 적용한다. 같은 주소와 SESSION_SECRET을 유지하면 서버 재시작 후에도 세션을 확인할 수 있다. 로컬 서버는 127.0.0.1에 바인딩한다. 교안별 접속 기록은 아직 추가하지 않았다.

`npm test`로 세션 생성·교체·로그아웃, 위조 인증·잘못된 출처·미등록 계정 거부, 비공개 파일 차단을 검증한다. Google 계정의 실제 로그인 팝업은 사람이 별도로 확인해야 한다.

로그인 코드는 `auth-dev/`에 둔다. 교안 배포가 덮어쓰는 `assets/`와 과목 폴더에는 서비스 코드를 두지 않는다. `.env.local`·학생 정보·비밀키는 커밋하지 않는다.


### 테스트 DB 저장 항목

Neon의 `login_dev_users`에 Google 고유 ID, 이름, 이메일, 최초·최근 로그인 시각, 로그인 횟수를 저장한다. 같은 계정은 새 행을 만들지 않고 갱신한다. Google 토큰·비밀번호·IP는 저장하지 않는다. 날짜는 TIMESTAMPTZ로 저장하며 화면에서는 한국 시간으로 표시한다.

새로고침은 로그인 횟수를 늘리지 않는다. Google 인증에 성공해 DB 저장까지 마친 요청을 집계하며, 이후 세션 생성 실패까지 고려한 출석 통계는 아니다. DB 장애 시 로그인 성공으로 표시하지 않고 안전한 오류 문구를 반환한다.

기존 메모리 세션에서 DB 세션으로 전환한 뒤에는 한 번 다시 로그인한다. 이후 서버 재시작에도 유효한 세션과 DB 사용자 기록은 유지된다. 교수 명단 관리와 명단 대조 가입은 아래 기능을 따른다. 교안별 열람 기록은 아직 추가하지 않았다.

### 학생 정보 등록·수정 (개발용)

Google 로그인 후 등록 정보가 없으면 입력 창을 표시한다. 이름은 Google 이름으로 미리 채우고 수정할 수 있다. 저장 후에는 요약과 내 정보 수정 버튼을 표시한다.

- 필수: 학번, 이름, 전공1, 전화번호
- 선택: 전공2 (삭제하여 빈 값으로 저장 가능)
- 학번은 영문·숫자·하이픈 4~20자이며 중복 등록을 제한한다. 실제 학번 규칙은 운영 전 확정한다.
- auth-dev/student-profile.js가 서버 입력 검증을 담당한다.
- GET/POST /api/student/profile은 인증된 세션의 Google ID로만 조회·저장한다. 클라이언트가 지정한 사용자 ID나 권한은 받지 않는다.

npm run db:setup은 login_dev_student_profiles를 추가한다. Google ID로 로그인 사용자와 연결하며 학번·학생 이름·전공1·전공2·전화번호·생성/수정 시각을 보관한다. 기존 로그인 테이블과 기록은 유지한다.

npm test에는 인증 없는 접근, 다른 사용자 ID 주입, 출처 검사, 입력 검증, 등록·수정·선택 항목 삭제, 중복 학번과 DB 오류 응답 검증이 포함된다. 학생 정보는 테스트 값으로 확인한다. 실제 학생 공개 전에는 수집 목적·보관 기간과 수강생 확인 절차를 확정해야 한다. 가입은 교수 명단과 학번·이름이 일치할 때만 완료된다. 학생 입력값으로 교수 권한을 부여하지 않는다.


### 교수 관리자와 명단 기반 가입 (개발용)

1. .env.local의 PROFESSOR_EMAIL에 교수 Google 이메일을 설정한다. 지정 계정은 인증된 Google 이메일과 서버에서 대조한다. 공개 코드에 실제 교수 이메일을 넣지 않는다.
2. npm run db:setup으로 과목·학생 명단·수강 연결 테이블을 준비한다. 초기 과목은 현재 공개 대상인 Python과 Java 두 과목이다.
3. 로컬 서버를 재시작하고 Google 로그인 후 관리자 링크 또는 http://localhost:3000/admin.html을 연다.
4. 과목을 선택하여 학생을 직접 등록하거나 UTF-8 CSV를 올린다. 기본 양식의 첫 행은 과목코드,학번,이름,분반이다. 과목별로 한 줄씩 작성하여 여러 과목을 한 파일로 등록할 수 있다. 과목코드 없는 기존 양식은 화면에서 선택한 과목에 등록한다. 학번 앞자리 0은 보존하며, Excel에서는 학번을 텍스트로 입력해야 한다.
5. CSV 미리보기에서 과목 신규·기등록 건수와 전체 명단을 확인한 뒤 등록한다. 150KB, 1,000명까지 지원하며 미리보기 유효 시간은 10분이다.
6. 학생은 Google 인증 후 명단의 학번·이름과 전공을 입력한다. 일치하는 명단이 있으면 가입 완료와 모든 수강 과목·분반을 표시한다.

동일 학번·이름은 하나의 학생으로 공유하고 과목별 분반을 따로 저장한다. CSV에 없는 기존 학생은 유지한다. 같은 과목·분반·학번은 CSV 등록 시 건너뛴다. 분반 변경은 수정 버튼으로 처리한다. 같은 학번에 다른 이름이 들어오면 전체 업로드를 거절한다. 파일 안의 중복 학번과 잘못된 행도 저장 전에 차단한다.

관리자의 수정 버튼으로 학번·이름을 정정하면 모든 수강 과목과 가입 프로필에 반영한다. 분반 수정은 선택한 과목에만 적용한다. 가입 후 학생은 학번·이름을 직접 바꿀 수 없고 전공·전화번호를 수정할 수 있다. 이름은 앞뒤 공백과 Unicode NFC를 정규화한 후 대조하며 내부 공백은 유지한다. 한 학번에 하나의 Google 계정만 연결한다.

Google 인증만 완료된 상태와 수강 명단 대조가 끝난 학생 가입 상태는 구분한다. 이전 단계에서 저장한 프로필은 자동 승인하지 않는다. 지정 교수는 학생 등록 폼 대신 관리자 링크를 본다. 학생 테스트는 Google 테스트 사용자와 LOGIN_ALLOWED_EMAILS에 등록된 별도 계정으로 수행한다.

학번·이름 대조는 수강 명단 확인이며 실제 본인임을 증명하지는 못한다. 운영 전 학교 이메일 또는 교수 확인 절차, 수집 목적·보관 기간을 확정해야 한다. 계정 연결 해제, 관리자 감사 기록, 공개 운영 사이트의 접근 제한은 아직 적용하지 않았다.

명단 관련 구현은 auth-dev/roster-schema.sql, roster-db.js, roster-validation.js, admin-routes.js와 public/admin.*에 있다. npm test로 API 권한과 CSV·가입 흐름을 검증한다. 개발 DB 통합 검증은 다음 명령으로 수행한다. 무작위 가상 계정·과목을 생성하고 해당 데이터만 정리한다.

    node --env-file=.env.local auth-dev/roster.integration.js

운영 main에는 병합·배포하지 않았다. 로컬 개발과 Vercel Preview 실행을 준비한 상태다.


CSV 과목코드는 관리자 화면의 목록에서 확인한다. 과목코드는 관리자 화면에 등록된 값을 그대로 사용한다. 한 학생의 여러 과목 수강은 허용하지만 같은 과목·분반·학번의 중복 행과 동일 학번의 다른 이름은 거절한다. 미등록 과목코드가 하나라도 있으면 전체 업로드를 거절한다. 모든 과목의 등록은 하나의 트랜잭션으로 처리한다. 미리보기 건수는 학생 수가 아니라 수강 행 수이다. 분반 앞자리 0을 유지하려면 Excel에서 텍스트로 입력한다.


### 과목 관리

관리자 화면 상단의 과목 관리에서 과목코드와 과목명을 입력하여 새 과목을 등록한다. 기존 과목은 목록의 과목명 수정 버튼으로 이름만 변경한다. 과목코드는 수강 연결의 기준이므로 변경하지 않는다. 동일 코드를 새로 등록하면 오류로 안내하며 기존 과목명을 덮어쓰지 않는다.

과목명은 1~150자이고, 과목코드는 영문 소문자·숫자·밑줄·하이픈 1~80자다. 새 코드는 CSV 업로드에 바로 사용할 수 있다. 이름 변경 후 관리자 선택 목록과 학생 수강 과목 조회에는 최신 과목명을 표시한다. 이미 열린 학생 화면은 새로고침하면 반영된다. 수강 명단과 분반, 가입 연결은 유지한다.

이 설정은 개발 DB의 수강 관리용이다. 강의자료의 course.yml 제목이나 공개 페이지를 자동 변경하지 않는다. 학기별 과목명 변경 이력을 따로 보관하는 기능은 없다.

과목 목록의 삭제 버튼은 과목명·코드 확인 후 빈 과목을 삭제한다. 수강생이 한 명이라도 연결된 과목은 서버와 DB 외래키로 삭제를 막는다. 마지막 과목을 삭제해도 새 과목 등록은 가능하다. 삭제는 개발 DB에만 적용하며 공개 교안은 삭제하지 않는다. npm run db:setup은 초기 Python·Java 과목을 다시 생성하므로 해당 기본 과목을 삭제한 후 재실행하면 복원된다.

### 과목·분반별 명단 조회

과목 선택 옆의 관리할 분반에서 전체 분반, 등록된 분반, 분반 미지정을 선택한다. 분반별 인원과 학번·이름 검색 결과를 함께 표시한다. 다른 과목으로 이동하면 전체 분반으로 초기화한다. 선택한 분반은 학생 직접 등록 폼에 미리 채우며 수정할 수 있다. CSV는 화면 필터와 관계없이 파일의 분반 값을 사용한다. 분반 표기는 원문 그대로 유지하므로 1과 01은 별도 분반으로 표시된다.


### 분반별 수강 삭제와 중복 입력

동일 학생을 같은 과목의 여러 분반에 등록할 수 있다. 수강 연결의 기본키는 학생·과목·분반이며 기존 데이터는 분반 포함 키로 마이그레이션한다. 회원 계정과 학생 정보는 하나로 공유한다.

직접 등록에서 같은 과목·분반·학번을 다시 입력하면 중복 안내와 함께 거절한다. CSV 파일 내 동일 수강 행의 중복도 거절한다. CSV가 기존 명단과 중복되는 경우 미리보기에서 기등록 건수를 안내하고 저장할 때 건너뛴다. 다른 분반으로 입력하면 별도의 수강 행을 추가한다.

명단의 수강 삭제 버튼은 확인 후 해당 과목·분반의 수강 행만 삭제한다. 다른 수강과 회원 계정·프로필은 유지한다. 마지막 수강 행을 삭제하면 학생의 수강 과목 조회는 빈 목록으로 바뀐다. 분반 수정 역시 선택한 수강 행에만 적용하며 다른 기존 분반과 충돌하면 거절한다.

수강 학생 목록의 이름·학번 열 제목을 클릭하면 해당 열로 정렬한다. 같은 제목을 다시 클릭하면 오름차순·내림차순을 전환하며 화살표로 방향을 표시한다. 기본은 이름 가나다순이며 분반 필터와 검색을 함께 적용한다. 동명이인은 학번, 분반 순으로 표시한다. 정렬은 화면에만 적용하며 DB 데이터는 변경하지 않는다.

### 로그인 화면 지원 과목

로그인 전에도 서비스 지원 과목(2026-2)을 표시한다. 관리자 DB 과목명에서 2026-2로 시작하고 뒤에 공백이 오는 과목을 조회한다. 과목 관리에서 이름을 바꾸면 다음 조회에 반영된다. 별도 학기 필드가 없으므로 과목명 앞의 학기 표기를 유지한다. 공개 API /api/public/courses는 과목코드·과목명만 반환하며 학생 명단은 반환하지 않는다.

전화번호 입력란에는 수업 관련 안내·상담을 위해 교수자가 개인 연락을 드릴 수 있다는 문구를 표시한다. 신규 가입과 정보 수정 모두 전화번호를 필수 검증한다. 기존 전화번호가 없는 계정은 로그인 후 추가 입력 폼을 표시한다. 관리자 수강 명단과 CSV에는 전화번호를 요구하지 않는다.


### 로그인 후 내 강의자료

학생은 Google 로그인과 명단 대조 가입, 필수 전화번호 입력을 완료하면 /courses.html로 이동한다. 자신의 수강 과목을 표시하며 같은 과목의 여러 분반은 카드 하나에 모은다. 내 정보 링크로 등록 정보를 수정하고, 교수는 전체 과목 목록과 관리자 링크를 사용할 수 있다.

auth-dev/course-pages.js에서 과목코드 603108을 2026-2-python_adv, 903131을 2026-2-java_basic 폴더에 명시적으로 연결한다. 과목명 변경과 관계없이 코드로 연결하며 새 자료 과목을 추가할 때 이 매핑도 추가해야 한다. 연결된 자료가 없는 과목은 준비 중으로 표시한다.

GET /api/my/courses는 세션과 DB 수강 정보를 검사한다. 학생 정보와 관리자 API도 서버에서 권한을 검사한다. 강의자료·이미지는 로그인 없이 공개하며 수강 삭제는 개인 수강 목록에 반영된다. 강의자료 링크를 로그인한 학생이 누르는 것만으로 공개 자료가 비공개로 바뀌지는 않는다.

개인정보는 DB와 인증 API에서만 제공하고 공개 HTML에는 넣지 않는다. 기존 Vercel 운영 사이트와 공개 GitHub 자료는 계속 공개하며 아직 로그인 프로그램을 운영 배포하지 않았다.


## Vercel Preview 준비

같은 GitHub 저장소의 feature/google-login 브랜치를 기존 Vercel 프로젝트의 Preview로 배포한다. 새 저장소나 Vercel 프로젝트를 만들 필요는 없다. main 병합은 Preview 검증 이후에 수행한다.

- server.js: Vercel Express 진입점. auth-dev/runtime.js가 환경설정·DB·세션 저장소를 연결한다.
- npm run build: 허용한 강의자료와 화면 파일만 public/에 생성한다. 생성물은 Git에 올리지 않는다.
- npm run db:sessions: 세션 테이블과 인덱스만 생성한다. 기존 수강 명단을 재생성하지 않는다.
- npm run dev: 로컬 로그인 서버 실행.
- npm test: 인증·권한·CSV·세션 공유 회귀 테스트.

최초 실행 전에 .env.local을 설정하고 npm run db:sessions를 한 번 실행한다. 기존 DB에 과목을 다시 초기화할 목적이 아니라면 npm run db:setup은 재실행하지 않는다.

Vercel 프로젝트 환경변수의 Preview 범위에 아래 값을 등록한다. 비밀 값은 공개 저장소에 올리지 않는다.

| 변수 | 값 |
| --- | --- |
| GOOGLE_CLIENT_ID | 기존 Google 웹 클라이언트 ID |
| SESSION_SECRET | Preview용 충분히 긴 임의 값 |
| LOGIN_ALLOWED_EMAILS | 테스트를 허용할 계정 목록, 쉼표 구분 |
| PROFESSOR_EMAIL | 교수 Google 계정 |
| DATABASE_URL | 개발용 Neon DB 연결 문자열 |
| APP_ORIGIN | Preview는 생략 가능. Vercel의 VERCEL_BRANCH_URL을 자동 사용한다. 운영 배포에는 실제 HTTPS 주소를 명시한다. |

첫 Preview는 위의 환경변수 다섯 개만 등록하고 배포한다. 자동 생성된 고정 브랜치 주소를 확인한 뒤 Google Cloud의 승인된 JavaScript 원본에 추가한다. APP_ORIGIN을 따로 등록했다면 그 주소를 사용한다. 로그인 테스트는 이 주소로 접속한다. 다른 배포별 주소는 Host 검사 때문에 로그인 API가 거절한다. 로컬 .env.local의 APP_ORIGIN은 http://localhost:3000으로 유지한다.

vercel.json에서 @vercel/static-build가 npm run build 실행 후 public/을 정적 배포 결과로 수집하도록 지정한다. @vercel/node는 server.js를 로그인 서버 함수로 배포한다. 기존 프로젝트에 수동 Build/Output Directory 설정이 있다면 Preview 배포 설정과 충돌 여부를 먼저 확인한다. 프로젝트 전체 설정을 바꾸어 운영 배포에 영향을 주지 않도록 한다.

세션은 login_dev_sessions에 저장한다. 세션 ID는 주소별 네임스페이스를 포함해 해시한 값으로 저장하며 로그인 시 ID를 재발급한다. 로그아웃은 DB 행을 삭제한다. 읽기로 유효기간을 연장하지 않으며 만료 행은 이후 세션 저장 때 최대 100개씩 정리한다. 만료 데이터가 남아 있어도 인증에는 사용하지 않는다.

공개 파일은 Vercel public/에서 제공한다. 서버 파일과 .env.local은 공개 파일 복사 대상이 아니다. 내 강의자료와 관리자 화면의 데이터는 인증 API로만 조회한다. 화면의 정적 HTML·JS가 보이더라도 학생 데이터가 포함되어 있지 않다.

공식 참고: https://vercel.com/docs/frameworks/backend/express

다음 단계: Vercel Preview 환경설정 확인 → 브랜치 push와 Preview 배포 → Google 로그인/학생·교수 권한/기존 강의자료 링크 확인 → 운영 적용 판단.

Preview 주소 자동 인식 참고: https://vercel.com/docs/environment-variables/system-environment-variables

과목 카드는 /과목폴더/index.html로 연결한다. 기존 /과목폴더/ 주소는 같은 index.html로 307 이동한다. Vercel에서 express.static의 폴더 기본 문서 처리에 의존하지 않는다.


### 정적 자료와 로그인 함수 배포
Express 자동 프리셋 대신 두 빌더를 명시한다. 빌드 단계에서 생성하는 public/이 정적 배포 결과로 수집되도록 @vercel/static-build의 distDir을 public으로 지정한다.
routes는 공개 파일을 먼저 찾고 나머지 요청만 server.js로 전달한다. /courses.html, /admin.html은 정적 최상위 파일로 생성하지 않으므로 서버의 세션·권한 검사를 유지한다.
서버 함수에는 sendFile에 필요한 auth-dev/public/ 화면을 명시적으로 포함한다. 환경파일과 학생 DB 자료는 정적 출력에 포함하지 않는다.
명시적 builds 설정을 사용하므로 Vercel 대시보드의 빌드 설정 대신 저장소 설정을 따른다는 안내가 나올 수 있다.

새 Google 로그인 성공 시 이전 URL의 profile 옵션과 관계없이 가입·전화번호 등록이 완료된 학생은 /courses.html로 이동한다. 이미 로그인한 상태에서 내 정보를 선택하면 정보 화면을 유지한다. 로그아웃은 /login.html로 이동하여 이전 옵션을 제거한다.


### 별도 운영 DB 초기 명단 이전
auth-dev/bootstrap-production.js는 빈 운영 DB에 테이블을 만들고 개발 DB의 과목·학번·이름·분반만 복사하는 일회성 로컬 도구다.
.env.local의 DATABASE_URL은 원본, Git 제외 파일 .env.production.local의 PRODUCTION_DATABASE_URL은 대상이다.
두 Neon 엔드포인트가 다르고 대상 public 스키마에 테이블이 없을 때만 실행한다. 계정·프로필·로그인 기록·세션·Google ID 연결은 복사하지 않는다. 기본 과목을 별도로 생성하지도 않는다.

사전 확인:
    node --env-file=.env.local --env-file=.env.production.local auth-dev/bootstrap-production.js

검토 후 실제 이전:
    node --env-file=.env.local --env-file=.env.production.local auth-dev/bootstrap-production.js --apply

테스트 학생 제외는 --exclude-student 옵션을 추가한다. 복수 옵션을 사용할 수 있으며 사전 확인과 실제 이전에 같은 옵션을 지정한다.
명단은 메모리에서 전달하고 터미널에는 건수만 출력한다. 대상 스키마 생성과 입력은 한 트랜잭션으로 처리한다.
완료 후 테이블이 있는 대상에는 재실행하지 못하므로 기존 운영 데이터를 덮어쓰지 않는다.
테이블 이름의 login_dev_ 접두사는 코드 호환을 위해 유지한다. 환경 분리는 실제 DB와 연결 주소로 수행한다.

교수 관리자 수강 명단의 가입 완료 일시는 학생 프로필을 처음 저장한 시각이며 한국 시간(Asia/Seoul)으로 표시한다. 이후 프로필 수정이나 재로그인으로 변경되지 않는다. 미가입 학생은 —로 표시한다.

### 운영 학생 가입

Vercel Production(VERCEL_ENV=production)은 검증된 Google 계정의 로그인을 허용하며 LOGIN_ALLOWED_EMAILS 제한을 적용하지 않는다. Preview와 로컬은 기존 허용 계정 제한을 유지한다. 일반 Google 계정 로그인만으로 학생 가입이나 교수 권한을 부여하지 않는다. 학번·이름 수강 명단 대조 및 필수 프로필 입력 후 개인 수강 과목을 조회할 수 있다. 교수 권한은 PROFESSOR_EMAIL과 일치하는 계정에만 부여한다. Google 인증 플랫폼의 게시 상태는 별도로 확인한다.
